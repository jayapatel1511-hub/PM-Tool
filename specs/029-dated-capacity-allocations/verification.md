# Verification: Dated Capacity and Project Allocations

**Date**: 2026-09-26
**State**: Pure domain arithmetic, additive schema, proposed-allocation API and supervisor availability override implemented; confirmation, grid, screen and product acceptance remain open.

`dotnet test tests/Hub.Tests/Hub.Tests.csproj --no-restore --filter 'FullyQualifiedName~AllocationsTests' -v:q -p:WarningLevel=0 -m:1 -nodeReuse:false` passed 4/4 on the isolated Mac worktree. These pure-function tests cover the 12-versus-8 plus unlinked-3 arithmetic in AC-CAP-01, a four-hour day override and holiday capacity in AC-CAP-02, exact decimal spread and a status reset on material edit. They do not exercise persistence, permissions, concurrent confirmation, project visibility or browser behavior. AC-CAP-03 through AC-CAP-05 are not accepted on this evidence.

The additive migration `DatedAllocations` creates availability overrides, project allocations, day overrides, unique active person/work/date links and person/date versions. It adds database checks for nonnegative availability/day hours, positive allocation hours, valid statuses/purposes/categories and ordered date ranges. `dotnet test tests/Hub.Tests/Hub.Tests.csproj --no-restore --filter 'FullyQualifiedName~AllocationSchemaTests|FullyQualifiedName~AllocationsTests' -v:q -p:WarningLevel=0 -m:1 -nodeReuse:false` passed 5/5 on a fresh ephemeral PostgreSQL database after regeneration. The schema test verified a four-hour override, duplicate active-link refusal, released-link reassignment and negative-hour refusal. `git diff --check` passed. The schema alone does not establish project/person/link consistency; transactional commands must enforce that. Product acceptance remains UNPROVEN.

The project API now creates, lists, reads, edits and cancels proposed allocations using the existing project transaction and idempotency record. It validates active same-project task/review references and the assigned person; a cancelled or replaced work link is retained as released history. List/detail filter out unrelated project members and return 404 for a hidden detail. An edit that changes only child rows advances the parent version. The focused `AllocationApiTests`, `AllocationSchemaTests` and `AllocationsTests` passed 7/7 on a fresh ephemeral PostgreSQL database after those fixes. This covers restricted-project hiding, foreign-project reference refusal, repeated create, child-only stale version, cancellation and link reuse. Confirmation, cross-project person/date version locking, over-capacity warning, aggregate privacy and browser UI are not accepted.

The supervisor availability API now permits a direct supervisor or Admin to set a dated non-sensitive capacity override and permits that person, direct supervisor or Admin to read the resulting rows. Writes lock the person row, require an expected override version and advance the person/date version. The same focused tests passed 8/8 after adding tests for supervisor/PM/read-only scope, a four-hour override, stale versions and the version row. This is an API path only: the workload grid has not yet been updated to display the new effective daily capacity, so AC-CAP-02 remains UNPROVEN in product behavior.
