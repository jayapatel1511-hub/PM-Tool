## Conflicts and limits to keep explicit

1. §41 colour-budget/sidebar decisions052-D2/D3 remain open; local dark implementation does not approve them or pilot activation. Do not enlarge the census allowlist to make a result pass. S10 remains conditional.
2. Planner labels.ts currently documents source-category accents, and PlanningBandBar uses confidence colours. The v2 fixed-meaning domain does not automatically authorize those same hues for every source/confidence. Recommended default: neutral source markers with existing text, teal planned/capacity figures, and confidence/visibility retained as words/outline cues. Root should reconcile the governing planner requirement before assigning strong hues; no invented confidence rule or changed P/A math.
3. TimeView currently carries entry totals/ByDay hours, **no verified leave or non-working-day facts**. Zero recorded hours cannot be treated as time away. Add a separately reviewed, current-viewer/day canonical availability read if needed; otherwise leave this part explicitly incomplete. Never infer leave from missing entries or expose leave reasons. Weekly time-away totals cannot identify exact days.
4. Status pills and lane colours are separate domains. A task bar can take its lane colour while its adjacent In Review pill stays the prescribed purple text/tint. Deliverable statuses are not automatically task buckets; do not force them through a task-lane mapper.
5. A project identity colour appears beside the project number; it must not replace health/status, become arbitrary section tint, or decorate a person. Existing inert legacy attributes need not be deleted merely because a source search finds them.
6. Lower-contrast lane hues require visible numeric/text equivalents. A token-valued computed RGB proves colour equality, not correct source token usage or semantic meaning.
