## Governing conflict and recommended dark default

The conflict is explicit: `spec-parts/14-weekly-planning-layer.md` FR-PLN-04 requires source-specific tints (Major project blue, Other project mint, Proposal lavender, Admin amber, Training peach), and a hatch for Private draft. `spec-parts/06-screens.md` §13.11's expanded planner row repeats source tint/private-draft hatch. Conversely, `31-visual-system-and-navigation.md` FR-VSN-04 fixes teal to people/capacity/hours and the other hues to different meanings; FR-VSN-06 reserves strong hatching for time away/on-hold and faint hatching for verified non-working dates; FR-VSN-09 permits only named tokens, with D2 still Open. This is a governing-spec exception, not merely a bad CSS literal.

Recommended **local dark** default: v2 source/category markers become neutral with their existing localized words; capacity quantities/bars use the teal domain; confidence bands remain separately identifiable by neutral boundaries/styles plus exact names/values; Private draft keeps lock + “Visibility: Private draft” + a distinct outline/dashed treatment, never the away hatch. Possible keeps its dotted treatment and “Confidence: Possible”. Preserve both facts when Draft+Possible+kept apply; one border-style override must not erase another fact. Keep off source tints/hatch unchanged. Root records this proposed §39/§13.11 exception alongside D2 before dispatch; do not silently edit formal spec text or mark a decision Accepted.

## Truth boundaries: amounts, certainty and dates

Authority is the existing server projection, not a client reconstruction:

- `Planning.cs:46–76,170–174,326–337`: Grid CellRow has **weekly** `timeAway`, `holidayHours`, `capacity`, `additionalAvailability`, three confidence totals, `ownDraftHours`, `provisional`; no dates of absence. It sums DayRow from PersonCapacity. Only the existing CellDetail read carries dated `normal`, `available`, `timeAway`, `holiday`, `additional`, `provisional`; ContributionList currently displays its normal/available/category columns (`ContributionList.tsx:20`). PlanningBandBar cannot recover dates from totals.
- `Availability.cs:30–41,151–158`: Vacation already has dated `normal`, `available`, `leave`, `holiday`, `provisional`, leave records and separate holidays. Person schedules are returned **only** when the caller manages that person; null schedules are not proof of a default calendar. The returned holiday catalogue includes office-specific entries and AvailabilityPerson has no office id; a catalogue date alone must not shade every person's cell. Positive **that person's day.holiday** is safer applicability evidence.
- `PersonCapacity.cs:9–42`: normal derives from the effective schedule/default capacity; available is reduced once; leave is the union/capped result of legacy and non-cancelled HR records. Unavailable/Reduced overrides and Unverified records set Provisional. Thus positive `timeAway`/`leave` is a **reported amount**, not automatically verified HR-approved leave. `08-rules-health-notifications-search-reports-audit.md` RES-03 explicitly preserves provisional legacy reductions. Do not recalculate or subtract them again.

| Fact available | Safe presentation |
| --- | --- |
| Finite positive server timeAway/leave, provisional=false | Named away swatch + exact reported hours; still no dates from a week aggregate. |
| Finite positive server timeAway/leave, provisional=true | Same reported amount may carry an away swatch **with the existing explicit Provisional qualifier**. Never label it approved/verified, invent a verified subtotal or present provisional free room as known. One provisional day does not identify which portion of an aggregate is verified. |
| zero capacity/available/remaining; empty bar; no planned entry; provisional flag alone | None proves time away. No inferred away hatch, source or leave date. A known zero stays a zero figure, not an absence claim. |

| person.weeklyHours=null; entry.projectId=null; schedules=null | Respectively use the server's daily/default-capacity result, retain unlinked work, and treat schedule detail as unavailable. None means0, away or no schedule. |
| day.holiday>0 | Known applicable holiday reduction: label its hours; faint calendar/holiday sample may identify that date. Keep any separately recorded additional availability and available hours; holiday is not personal leave. |
| day.normal=0, available=0, or a Saturday/Sunday date alone | Not sufficient evidence for a generic non-working-calendar claim. Normal may be0 because contracted/default hours are0, and person schedules can include weekends. DayRow.category=null only means no derived leave category. |

Weekly/monthly away must be a **small labelled swatch beside the quantity**, not a full cell/button fill or a spatial block that pretends the person is absent for that entire interval. On Vacation's actual daily cells a swatch can identify partial/full reported leave without pretending a four-hour absence is a whole day. Year mode must retain aggregation wording. Append time-away/provisional words to the weekly button's explicit aria-label: its current custom name otherwise overrides child text. Keep visible text/legend as well as accessible names (FR-VSN-20 / AC-VSN-03).

There is no explicit daily isWorking/isNonWorking field in either existing daily DTO. `PersonCapacity.Calendars:47–55` has the actual effective-date calendar/office-holiday predicate; `Normal==0` cannot replace it. For complete faint non-working-day coverage, request a **root-owned optional visual-system daily truth boolean** from that canonical calendar through existing permitted daily reads, omitted off. Do not expose private schedules, add per-cell requests, infer every weekend, or add a migration. This contract is a separate small dependency; the truthful weekly swatch/source/draft batch can ship dark without pretending that daily calendar coverage is finished. No Time consumer or S32 bridge is included here.
