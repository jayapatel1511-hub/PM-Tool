## Small metadata addition, explicit manual registration

Recommended root schema addition: six nullable columns on DocumentLink; all existing rows remain NULL with no inferred backfill:

| Property | Type / limit | Meaning |
|---|---|---|
| SourceSystem | string, max200 | User-declared source, e.g. SharePoint or a named external register; not connector verification. |
| StableSourceId | string, max200 | Optional exact external identifier; absence remains unknown. It is not a URL-derived identifier. |
| DeclaredRevision | string, max50 | Optional manually declared revision; absence means not recorded. |
| ReferenceRegisteredBy | Guid? | Actual authenticated user who most recently explicitly registered this metadata. Separate from AddedBy. |
| ReferenceRegisteredAt | DateTimeOffset? | Server time of that registration. Separate from AddedAt. |
| ReferenceDeliverableId | Guid? | Canonical deliverable captured when registration occurs; never a caller-provided arbitrary target. |

Use one all-null legacy/unregistered state. A registered reference requires nonblank SourceSystem and both registration provenance values; StableSourceId/DeclaredRevision/ReferenceDeliverableId may be NULL. A nullable user FK must not break existing missing-author history; root should follow existing identity retention rather than add deletion cascades. Root owns constraints, migration/snapshot and audit fields. No verified flag, remote timestamp, extra content/version table or file bytes.

Append optional `reference` to the existing AddBody, with null omitted from serialization. Its exact input shape is `{sourceSystem:string, stableSourceId?:string|null, declaredRevision?:string|null}`. Do not change the old Url/Title/LinkType order, validations, defaults or create reply. Existing callers may omit it while flag on. Provide the same optional complete replacement object on PATCH `/links/{id}`; explicit PATCH `reference:null` clears the six metadata columns while on. Omission retains metadata except the address-change rule below. Do not introduce a second endpoint or mutation engine for the same link.

Input rules while people_screens is on:

- Trim the three input strings, turn blank optional values into NULL, require SourceSystem1..200, cap stable ID200/revision50, reject controls/newlines and non-string values. Accept ordinary Unicode and punctuation in revision labels; do not impose the separate revision-convention feature's pattern or infer an ordering. Reject unknown properties **inside the new reference object**, including caller-supplied registrar/time/target, verification or current revision. Retain old handling of old top-level fields.
- Resolve the canonical owner and current project access before reading/writing metadata. Project owner captures NULL target. Deliverable owner captures its own deliverable ID. Task owner captures its current same-project, non-deleted DeliverableId if present, otherwise NULL. Validate the actual parent relationship; an unrelated/foreign/deleted deliverable cannot be selected by a body or guessed from a URL. Metadata alone cannot reparent an item.
- For a task, the input label/hint must say its declared revision is compared with the task's linked deliverable, when one exists. An unrelated external reference can retain source/ID with no declared revision; never silently claim it matches that deliverable. A Project or standalone-Task link may record an external revision, but has no comparison target.
- Registration stamps the authenticated user and one server-clock time. Omitted metadata on creation keeps all six NULL. A title/type-only edit retains registration provenance. Replacing the reference explicitly restamps it, including deliberate re-registration after a task parent changed. None of this changes AddedBy/AddedAt.
- If URL/path changes and PATCH omits `reference`, clear the six metadata fields in that same canonical link transaction. Old declaration/provenance cannot silently migrate to a new address. If URL plus a complete reference are supplied, validate both and register against the new address atomically. Explicit null clears. Refused URL/reference/version/permission leaves the link, version and audit unchanged.
- Reuse current CanAdd/CanChange, Http.CheckVersion, SaveChanges/audit and soft-delete paths. Own links remain author-or-PM with existing project write gates; being the metadata registrar grants no extra right. Inherited links remain uneditable from a Task. A reference edit increments the link RowVersion once; it never increments a deliverable/version or clears a coordination gate.

While off, omitted/null AddBody reference keeps the legacy command and reply exactly. A non-null AddBody reference, or any PATCH reference property, refuses404 before writing; ordinary old PATCH fields remain usable. Off reads omit all new metadata, including values stored while on. Turning off does not erase data. If an old off-mode URL edit changes the address of a previously registered link, perform the same metadata invalidation internally so re-enabling cannot revive a declaration attached to the old address; this is a necessary safety invariant, not permission expansion. An off-mode title-only edit retains it.

## Canonical comparison and unknowns

Compare trimmed recorded revision strings by ordinal equality. The rule is **different**, not “older”; C versus D is a mismatch, and D versus C is also a mismatch. Do not parse letters, numbers, filenames or timestamps to select a winner. No claim about current external contents follows from matching metadata.

| Canonical state | Read/UI result |
|---|---|
| No registered DeclaredRevision | `NotRecorded`; “Declared revision not recorded.” No green/current claim. |
| Declared value; registration had no deliverable | `NoDeliverable`; show declaration and manual provenance, “No linked deliverable for comparison.” |
| Task's current deliverable differs from captured ReferenceDeliverableId, including removal | `TargetChanged`; keep historical declared/provenance facts, “Linked deliverable changed; register the reference again.” Do not compare with its new parent. |
| Captured target is deleted, foreign, missing or inaccessible | `TargetUnavailable`; no target label/revision/rights are leaked and no match/mismatch is invented. |
| Visible coherent target, Revision NULL/blank | `CurrentNotRecorded`; show declaration and “Current registered revision not recorded.” |
| Both values known and equal | `Matches`; “Declared D, current registered D · manually registered.” A neutral fact, not verified file/current-content approval. |
| Both values known and unequal | `Different`; visible text **“Declared C, current D”** plus manual provenance/registered-current explanation. Use the existing warning treatment, not an unlabelled colour or project-status change. |

Current revision and owner/discipline labels are live reads from the same permission-scoped snapshot. ReferenceDeliverableId is registration context, not proof that its captured revision is still current. Deliverable.RowVersion may be returned as an observed read/version fact but must never be displayed as a drawing revision. If a coherent target exists, expose its actual key/name/status/current registered revision; terminal status does not prevent displaying an existing mismatch. No statuses, revision claims or rights are inferred from URL reachability.

Task-parent changes create a stale-comparison state; they do not mutate link metadata in a GET. A direct deliverable link has that deliverable as both owner and target. An inherited row on a Task retains its **deliverable-owned** link ID, RowVersion, captured target and provenance; its caller-context CanChange stays false. Do not duplicate it into Files under every Task or count it more than once.

## Files query, missing-link anti-join and typed read

Extend only GET `/files`, gated inside its existing handler. New optional raw-string query parameters: `disciplineId`, `addedById`, `addedThisWeek`. Raw strings permit off mode to ignore malformed new URL values instead of model binding them before the flag check. Existing `projects`, `q`, `type` retain their established dark behavior.

While on: empty new values mean absent; nonempty discipline/addedBy require a single nonempty Guid; addedThisWeek accepts exact `true` or `false` only (false means no week restriction). Malformed IDs/boolean or comma lists refuse400 with the offending field. A well-formed unknown/out-of-scope ID returns an empty matching cohort without disclosing hidden labels or existence. Filter by actual IDs, not display names. Different users with equal names stay distinct.

- Discipline means **global Discipline.Id**, joined from each owned work item's ProjectDisciplineId. This supports one discipline across multiple scoped projects. Use the Task's own discipline for Task links and the Deliverable's own discipline for Deliverable links; Project links have no discipline and are excluded by a selected discipline. Do not invent a Project-link discipline or use an author's home discipline. Retain historical/inactive discipline labels if actually joined.
- Added-by means DocumentLink.AddedBy, not ReferenceRegisteredBy, owner, task assignee or a display-name lookup. Missing-author links still belong to their real AddedBy value; no fake Person ID or new directory permission follows. Renaming/deactivating a user must not change membership of this filter.
- Added this week means AddedAt within Monday00:00 to next Monday00:00 in **organisation time**, capped at the server's current instant. Reuse Clock.Zone/LocalDate and one TimeProvider instant; convert local boundaries with the actual time zone/DST rules, not seven UTC days or the browser zone. It never uses registration or edit time. Return asOf, organisation zone and local week dates so the UI/fixture does not manufacture them.
- Apply all link predicates before the existing2,000 cap and author/context projections. While on use a stable title then link-ID tiebreak for capped equal-title records. Keep old off ordering/projection untouched. Link-only filters must not select missing-link rows by absence of results.

The “Deliverables with no link” list is an **independent server anti-join**: in current permitted Scope.Projects, live deliverables with `!DeliverableStatus.IsTerminal(status)` and **no live direct DocumentLink where ItemType=Deliverable and ItemId=that deliverable ID and matching ProjectId**. Open includes Not Started, In Progress, In Review, Revision Required, Ready to Issue and On Hold; excludes Issued, Accepted and Cancelled. Soft-deleted links no longer satisfy the anti-join. Soft-deleted deliverables and excluded projects never appear.

Project links and task-only links do not satisfy this direct-deliverable requirement; inheritance currently runs from Deliverable to Task only. A live direct link of **any** type/author/date/revision metadata satisfies it, including a mismatched or unregistered link. Searching/filtering that existing link out must not create a false missing-link alert. This list does not certify an externally accessible or correct document.

Reuse the existing page layout with a separate labelled section, rather than inventing a new navigation mode. Scope and discipline apply to both sections; `q` applies to link title/URL in the links section and deliverable key/name in the missing section. Link type/added-by/week apply only to actual links. Say this next to the filters/missing section when those filters are active. Missing membership's anti-join must ignore **all** link filters, including q. Render an independent empty/error/truncation state; zero matching links must not hide known missing deliverables.
