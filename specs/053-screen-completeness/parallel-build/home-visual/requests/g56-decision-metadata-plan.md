## Consequential provenance choice for root to freeze

The spec says “owner organisation (internal, or each ExternalParty)” while the actual ExternalParty row can represent a **person**. Literal per-party-ID median rows can therefore become forbidden per-person metrics. Proposed safe default: within the **current readable project**, group all internal owners into one Internal bucket; group external owners by their actual nonblank, trimmed **ExternalParty.Organisation** value. Do not display contact names/IDs in metric rows. Equal exact organisation strings combine contacts; no cross-project identity or fabricated organisation record is created. Use ordinal equality after trimming; case/spelling variants remain distinct until there is an explicit canonical-organisation requirement. Root must resolve this parenthetical-versus-model conflict before freezing implementation; do not silently implement per-contact figures.

External missing/blank/missing-party or inconsistent owner data contributes to an **unattributed/invalid count**, not an “Internal” bucket, contact-name fallback, zero-day observation or invented organisation. Inactive parties with retained genuine organisation remain attributable; inactive does not erase history. Require actual same-project party joins even for historical rows so corrupt foreign IDs cannot leak an organisation.

Recommended bounded historical meaning: **live registered values**, explicitly labelled “All currently Decided decisions in this project; current registered owner organisations and dates.” Existing dates and owner relationships can be measured without backfill, but they cannot prove historical organisation at decision time. Renaming a party organisation, reassigning an owner or correcting a requested date changes this live summary. Do not call it an immutable turnaround history, infer old organisation from the audit recorder or backfill a snapshot. If root instead requires organisation-at-outcome history, that needs a separately frozen additive capture/correction/reopen contract; old unknowns must remain unknown. No new outcome table or snapshot is necessary for the recommended live-read meaning.
