## Proposed import contract

### Entry points and supported formats

Add project-scoped POST `/projects/{id}/deliverables/import-preview` and POST `/projects/{id}/deliverables/import`. Both require register_screens and normal project visibility, then PM/eligible current DL authority. Import is independent of project_import, visual_system, revision_check, delivery_screens and screen_patterns. No Admin-only project-import route is reused as an authorization shortcut.

Proposed strict JSON body: `{format:"csv"|"xlsx", content, worksheet?, sourceReference?, defaults}`; commit adds `{previewFingerprint, projectRowVersion, reason?}` and requires Idempotency-Key. CSV content is text; XLSX content is base64 original bytes, decoded with a bound before reading. Reject a wrong discriminant/extra member, mismatched file signature, unsupported file and empty data. Source reference is optional provenance, not an eligibility requirement. Multipart is an alternative open transport decision, not a second parser. Browser sends XLSX bytes to the server; do not use file.text() or pretend an XLSX is CSV.

Current isolated draft defaults, supplied by root for review: CSV256KiB original UTF-8 bytes; XLSX2MiB compressed and16MiB total expanded entries; at most1000 nonblank data records,100 columns,128 ZIP entries. These replace the earlier8MiB/32-column/256-entry suggestions in this handoff only; they are not a formal global-limits decision. Request body allowance must account for base64 overhead and JSON. Bound original bytes before decoding/hashing; check declared and actual expanded bytes while streaming each entry, before adding it to the bounded in-memory parts. Do not merely trust ZIP directory lengths. These are draft drawing-import limits, not existing endpoint support.

Use the existing framework TextFieldParser CSV conventions (comma delimiter, quotes, escaped quotes, BOM, CRLF/LF). Extract only a format-level bounded CSV reader if sharing it with project import; do not share its private Admin/project_import validator or change its five-header policy. Preserve multiline quoted values and meaningful source record/physical row location.

For XLSX, implement one narrow server-side OpenXML table reader using existing ZIP/XML platform primitives, or a separately approved primary-source-reviewed library. The present Export writer cannot parse workbooks. Read shared/inline strings and typed cells; prohibit DTD/entity resolution, external links/relationships, macros, encrypted archives, executable/evaluated formulas and cached formula substitution. Reject `.xls`, `.xlsm`, `.ods` and arbitrary ZIPs explicitly. One visible sheet can be selected automatically and named in preview; multiple eligible sheets require explicit selection. Check all nonblank rows in the selected sheet, including filtered/hidden rows, and mark hidden rows in preview; never silently import only what a spreadsheet filter happens to display. Reject merged cells crossing the import table. Never fetch linked data.

### Column mapping and normal create values

Offer a downloadable header template, with header-based mapping rather than position-based guessed schemas. Recommended canonical headers below; order may vary, names match trimmed case-insensitively, duplicate/unknown headers are errors. No fuzzy aliases until a real drawing-list sample is approved. Optional missing columns are permitted; every nonblank unsupported column must be diagnosed, not silently discarded.

| `client drawing number` | Optional literal text max120; reuse Number()/Matches(). Preserve leading zeros. Missing stays null; `C12` against `C-###` creates with a visible warning. Duplicate client numbers alone do not update/refuse records or establish identity. |

For source identity/client number, numeric XLSX cells are refused with a format-as-text correction so lost leading zeros cannot be invented. CSV formula-looking text is literal input and receives the existing export escaping on output; XLSX formula cells are never executed or accepted as guessed cached text.

Reject imported `id`, Tuesday `number/key`, status, purpose-of-issue, issued date/to/by, return code/date, transmittal, actual hours, review evidence and immutable history columns with explicit reasons. Do not ignore a legacy register's issue columns while claiming its issuance was imported. A separate legacy-history migration would need its own spec, provenance and authorization; S34 is create-only drawing-list intake.

Defaults are explicit selections echoed in preview and fingerprinted. An absent column is not a permission to choose the first person/type/reference. Empty or ambiguous vocabulary has a corrective error and a link to the established configuration surface if permitted. Never change organisation lists, project numbering patterns, roles or existing work while importing.

### Preview, duplicate handling and provenance

Preview parses/checks every readable row and returns `{sourceReference?, format, worksheet, contentHash, previewFingerprint, projectRowVersion, rows, creates, exists, errors, warningRows, canCommit}`. Each row has source location, optional source key, original bounded input, normalized create values, resolved display labels/IDs, `Create|Error`, errors[], warnings[] and explicit effective defaults. The optional compatibility counter exists is0 in this create-only contract; an Exists classification needs a separate approved identity rule. Parser-level corruption returns a file error when row recovery is unsafe. Preview has no business writes: no key reservation, member creation, activity, notification, durable preview or import receipt. Root must give this exact preview route a middleware bypass marker so even a caller-supplied Idempotency-Key cannot turn it into a persisted generic POST receipt; omitting the key only in the UI is insufficient.

Revised O1 default: accept ordinary drawing lists without a source-reference form step or source-key column. Required behavior is full preview plus atomic create-only commit. Within the existing atomic receipt retention, exact same body/key retries return the original created set. A new deliberate key/file submission is a new import intent, not an upsert. Preview can show possible duplicate warnings from matching permitted titles/client numbers, but those values do not prove identity and must not silently convert a Create into Exists or an update. Do not claim permanent cross-file deduplication from a24h request receipt.

Optional explicit stable source reference/key may be displayed and recorded on the existing Created activity as supplied provenance, with no invented external author/original issue date. Duplicate supplied keys within a file are errors. Stable cross-file Exists recognition needs an independently approved persistence/retention contract; a new provenance table is **not authorized** in this slice. Do not query activity history as if it were a unique-key database. No soft-deleted record is restored, no existing deliverable is updated/deleted, and absent optional identity is never an error. Source row position/file hash can describe this batch without masquerading as stable external identity.

Preview fingerprint covers the parser contract version, project, sourceReference, normalized row order/identity/content/defaults, content hash/format/sheet, resolved reference IDs+versions, project version and pattern relevant to warnings. No storage token/secret is needed: commit reparses/revalidates and recomputes it. Changed file/defaults resets preview and key in the UI; changed server meaning requires a new preview rather than silently accepting different rows. Preview must clearly say it is not a reservation and proposed Tuesday keys are not guaranteed.

### Commit authority, versions, atomicity and replay

1. Gate flag/project before returning any result, including replay. Check current Writable and CreateDeliverable for **every** effective ProjectDisciplineId. PM can span authorized active project disciplines; a DL can import only rows in their current active own-discipline scope. A mixed unauthorized file is rejected as a whole, never filtered down to an authorized subset. ReadOnly, lost membership/lead, restricted/out-of-scope project and read-only project states retain canonical denials. Complete requires PM and the normal correction reason; Archived is refused. No new rights are inferred from a system role alone.
2. Require a nonempty bounded Idempotency-Key and the captured project version (428 missing,409 stale) on a new commit. Load scope, take the existing project lock, reparse/check every row and all active references, owner fallback, dates, pattern, duplicate identities and preview fingerprint in the same transaction. A changed reference, pattern, membership or competing import requires a fresh preview; preserve entered bytes/defaults and old baseline. No automatic stale retry on a new version. Project version does not substitute for the reference fingerprint or unique identity constraint.
3. Only after all validations pass, reserve keys for Create rows and invoke a shared **in-process** canonical deliverable creator under that same transaction. Extract the narrow validation/creation operation from E5; do not POST one row at a time, call an HTTP handler in a loop with its own commits, or independently reimplement lifecycle/review/member/key behavior. All records, normal Created logs, membership changes, notification/outbox rows and successful receipt commit together; failure at row40 rolls all40 back, including keys. Concurrent manual creates still use normal key reservation. No mapping/schema addition is implied.
4. New records are Not Started with no issue rows, no current issue pointer, no response, no SourceRevision/review record and no inferred acceptance. Source status or revision is not an issuance command. The original file is not stored in activity or a new document/file service. For each Create, set Source=Import on its existing Created activity and add a bounded note Snapshot containing batch/row/hash/format/sheet plus source reference/key only if actually supplied. Exactly40 created deliverables means exactly40 Deliverable Created entries, no second synthetic Imported entry per item. Exists/error/preview creates no deliverable event. 5. Reuse the existing transactional body-hash receipt primitive, with a typed drawing-import authorization seam. E8's generic receipt is inadequate, and its current `/import` replay branch is Admin-only. Root should add an exact endpoint metadata/dispatch seam plus a narrowly extracted atomic receipt helper, preserving all existing Planning/project-import behavior. Avoid adding a separate receipt table if the existing IdempotencyRecord can hold the bounded compact response.
6. Hash path+project+format+original content+sheet+optional source reference+defaults+fingerprint+captured version/reason. Same actor/key and exact body returns the original compact successful result and created IDs, with no reinsert/audit/notification. Same key with changed body/path/project is409. Current flag/project/PM-or-own-DL authority is rechecked **before replay**, without demanding the now-obsolete original project baseline again. No replay when flag off or authority revoked. Lookup same successful receipt precedes new-commit stale-version checking. An absent/expired receipt cannot promise permanent duplicate prevention: require a new explicit preview showing creates/possible duplicate warnings, retain existing rows unchanged, and document that replay safety has a retention limit. Failed commits have no successful receipt. Racing identical live keys serialize to one committed result using the existing transaction/lock pattern; do not expose success before transaction+receipt commit.

Commit result: `{batchId, projectId, created, exists, rows:[{sourceRow, classification, id?, key?, rowVersion?, warnings}], projectRowVersion}`. Keep it compact enough for the retained receipt; original file/preview text belongs outside it. Return real IDs/versions for created records, no guessed key/zero placeholder. After uncertain network outcome keep the exact body/key; do not offer a fresh-key retry as a safe equivalent. New deliberate content needs a new preview and key.

Notifications, if normal create produces them, remain transactional and deduplicated on replay; don't send per-row network email inside the transaction. Do not suppress or fan out a different notification policy without explicit review. No observer-facing total may count uncommitted/failed rows.

Project number/name, existing PM display name, generation time in org zone and safe filter description may be metadata, not extra person columns. Use only explicit eight-column client rows/columns; never serialize the full DeliverableRow then merely hide columns in Excel. Existing CSV escaping protects text formulas; XLSX inline strings must remain strings and dates use typed cells. Generate one normal Exported access event, with no data rows/file bytes in it. No new exported-file storage or operational-data mutation. See O5 for the distinction between excluding person fields and detecting names inside arbitrary drawing titles.
