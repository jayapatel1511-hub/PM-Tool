## A. Proposed summary contract

Owner flag: **register_screens**, independent of screen_patterns, people_screens and capacity_screens. Add only GET `/projects/{projectId:guid}/reviews/discipline-summary`, returning a typed `Ok<ReviewDisciplineSummary>`. Check current flag and `access.Project(projectId, false)`; authorized project readers, including read-only users, may read. Missing/restricted project follows existing indistinguishable404 behavior. No new person-scoped permission, ranking/filter or reviewer-level field.

Read all relevant packages, rounds and discipline assignments in one repeatable-read snapshot, with explicit project/package/round/project-discipline integrity. Do not inner-join away malformed history or read through a capped review list, manifest row, finding page, source count or current browser filter. This read writes no business/activity/Seen/receipt/evaluation state.

**Recommended population, for root to freeze:** currently Approved, live/non-deleted packages of exactly the authorized project. A discipline contributes one package sample only when it is required in that package's approved current round. Identify it by stable ProjectDisciplineId, with global DisciplineId/name/inactivity as labels; do not group by the package's single coordinating discipline or by reviewer. A package with Civil and Electrical contributes once to each appropriate discipline, never once per finding/deliverable/reviewer. Inactive historical disciplines remain visible and labelled; no sample becomes a new active assignment.

For each discipline row, ApprovedPackageCount is the entire authorized project's current Approved population; EligiblePackageCount is the subset requiring that discipline in the current round, and NonApplicablePackageCount is the remainder. Only eligible packages can become PackageSampleCount or UnavailablePackageCount. A package that does not require the discipline is not applicable, never missing data.

For one such package/discipline, rounds to approval is the count of distinct **started** rounds at or before the approved current round in which that same discipline had a required assignment. Earlier Electrical-only rounds do not count toward Civil; unstarted drafts do not count; use actual round IDs and StartedAt rather than RoundNumber as an answer. Historical round status may now be Superseded, so filtering historical samples to status Approved would erase real rounds. Duplicate/cross-project associations are an integrity refusal, not silently deduplicated plausible numbers. A missing timestamp needed to establish a legacy sample is unavailable, not a fabricated zero.

Compute median and maximum across those per-package counts. Median of an even set is the arithmetic midpoint (1,2 →1.5), without integer truncation. Approved current round missing/unstarted timing produces an unavailable package sample; display its count and identify the estimate as based on the remaining recorded samples. If root requires an all-or-nothing statistic instead, return null whenever UnavailablePackageCount>0 rather than silently claiming a complete population.

**Root-accepted timing clarification:** for each distinct qualifying discipline assignment in a started round of this same eligible approved-package population, use that `DisciplineReview` row's recorded **latest terminal discipline result** (Approved or Changes Required) at `DisciplineReview.DecidedAt` minus the actual `ReviewRound.StartedAt`. There is no DisciplineReview.StartedAt field. This is elapsed UTC duration divided by86,400 seconds, not business days, local date subtraction, WaitingDays or time to respond/verify a finding. In Review timestamps are not terminal. Pending, missing, cleared or negative timestamps do not enter the time median; report unavailable timing assignment-round counts. Exact zero duration is valid. Compute before rounding; display a documented one-decimal value without changing the underlying decimal median. Label it **Median days to discipline decision** and disclose that it uses the current stored latest terminal decision, not immutable first-result or whole-round completion history. No CompletedAt addition is needed for this accepted interpretation.

DecidedAt is the latest recorded result, not an immutable first-result event. A reassignment or later decision can change this input and package approval; the summary is a current factual read, not a historical performance report. If the desired metric is instead whole-round completion time or first terminal result, this source cannot prove it: root must separately specify/capture that actual fact and historical-unknown behavior. Do not reconstruct it from UpdatedAt, activity ordering, response outcomes or a guessed max timestamp.

Recommended constant discriminators: Population=`CurrentApprovedPackages`; TimingBasis=`LatestTerminalDisciplineDecision`. No reviewer/actor IDs/names or findings/response-based completeness score. Per discipline, `EligiblePackageCount + NonApplicablePackageCount = ApprovedPackageCount` and `PackageSampleCount + UnavailablePackageCount = EligiblePackageCount`. For that discipline's eligible started assignment-round population, `TimedAssignmentRoundCount + UnavailableTimingAssignmentRoundCount = StartedAssignmentRoundCount`: exactly one qualifying discipline assignment per round, never a global package-round count. No qualifying packages means known zero sample counts and null metrics, not0 rounds/days; nonrequired packages remain NonApplicablePackageCount rather than unavailable samples. Missing label has an explicit unknown state while stable IDs preserve grouping. Empty/no samples, partial timestamp coverage and failed current read are separate UI states. The pure calculator accepts typed factual package/round/assignment inputs with no EF/clock/actor dependency; keep it internal to the new feature file unless root requests a separate Domain file.

Mount a compact discipline table beside R1, with population/timing labels and sample denominators; it ignores review-list and finding-list filters and pagination. No automatic drilldown is necessary to meet FR63. Query key proposal `['review-discipline-summary', projectId, viewerId, registerOn]`; disable/unmount off. Hide cached statistics after current-key refusal; identity/flag changes must not show prior values. Root invalidates on package/round/assignment/finding changes that can recompute approval, source publication/replacement, project membership/visibility, discipline/reference and setting changes. Defaults changes alone do not rewrite metric history.
